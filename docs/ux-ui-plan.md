# แผน UX/UI ระบบตารางเวรและสรุปรายได้สำหรับพยาบาล

สถานะเอกสาร: Approved specification v1 — เริ่มพัฒนาระบบจริงแล้ว

## 1. เป้าหมายผลิตภัณฑ์

ระบบเป็น LIFF mobile web app สำหรับพยาบาล ใช้บันทึกเวร คำนวณชั่วโมงและรายได้โดยประมาณ แจ้งเตือนผ่าน LINE และสร้าง PDF สรุปส่วนบุคคล ผู้ใช้แต่ละคนเห็นเฉพาะข้อมูลของตัวเอง ไม่มีบทบาทผู้ดูแล

หลักการสำคัญ:

- ใช้งานหลักด้วยมือเดียวบนโทรศัพท์
- ผู้ใช้ใหม่ต้องตั้งค่าและเพิ่มเวรแรกได้โดยไม่ต้องอ่านคู่มือ
- แสดงที่มาของยอดเงินทุกก้อน ไม่ซ่อนสูตรไว้หลังยอดรวม
- เมื่อข้อมูลไม่ครบให้สื่อสารความไม่แน่นอนอย่างตรงไปตรงมา
- ใช้สีชมพูพาสเทลเป็นหลัก อนุญาต gradient เฉพาะปุ่มและจุดเด่นขนาดเล็ก และไม่ใช้ emoji เป็น icon

## 2. User flow

```text
เปิดจาก LINE
  -> ตรวจสอบตัวตน
  -> ใช้ครั้งแรกหรือไม่?
       -> ใช่: ตั้งค่ารายได้ -> ตั้งค่ารอบ -> ตรวจประเภทเวร -> ตั้งเตือน -> หน้าหลัก
       -> ไม่ใช่: หน้าหลัก

หน้าหลัก
  -> เพิ่มเวร -> ตรวจเวลาซ้อน -> บันทึก -> คำนวณใหม่
  -> เพิ่ม OT เคสด่วน -> บันทึก -> คำนวณใหม่
  -> เพิ่มรายรับ/รายการหัก -> บันทึก -> คำนวณใหม่
  -> ดูสรุป -> ตรวจข้อมูล -> ยืนยันข้อมูลครบ -> สร้าง PDF

ก่อนถึงเวร
  -> Supabase Cron -> Edge Function -> LINE Messaging API -> ข้อความแจ้งเตือน
```

## 3. Information architecture

เมนูหลักด้านล่างมี 4 รายการ:

1. หน้าหลัก — สิ่งที่ต้องรู้ในวันนี้และยอดรอบปัจจุบัน
2. ตารางเวร — ปฏิทิน เพิ่ม/แก้ไขเวร และตรวจเวลาซ้อน
3. การเงิน — รายรับ รายการหัก สถานะข้อมูล และสลิป
4. ตั้งค่า — รอบเงินเดือน รายได้ ประเภทเวร และการแจ้งเตือน

ปุ่มเพิ่มข้อมูลใช้ปุ่มหลักในบริบท ไม่ใช้ floating action button ซ้อนกับ bottom navigation เพื่อป้องกันการกดผิดใน LIFF browser

## 4. Screen inventory

### Onboarding

- Step 1: ฐานเงินเดือน ค่าใบประกอบ อัตรา OT และชั่วโมงปกติ
- Step 2: วันเริ่มรอบและวันสิ้นสุดรอบ
- Step 3: เวรเช้า/บ่าย/ดึกและค่าเพิ่ม พร้อมตั้งการแจ้งเตือนหลายเวลา
- ทุกช่องอธิบายหน่วยชัดเจน และกลับมาแก้ภายหลังได้

### Home

- รอบเงินเดือนปัจจุบัน พ.ศ.
- ยอดสุทธิ: แสดงช่วง ±500 บาทเมื่อข้อมูลไม่ครบ และยอดเดียวเมื่อยืนยันครบ
- ชั่วโมงทำงานเทียบเป้าหมาย
- เวรถัดไปและเวลาแจ้งเตือน
- ทางลัด เพิ่มเวร, OT เคสด่วน, รายรับ/รายการหัก
- breakdown แบบย่อ

### Calendar

- เดือนปัจจุบันและปุ่มเปลี่ยนเดือน
- มีปุ่มเดียวสำหรับสลับมุมมอง โดยค่าเริ่มต้นเป็นแบบย่อ ปุ่มแสดง “ขยาย” และเปลี่ยนเป็น “ย่อ” เมื่อเปิดมุมมองข้อความ
- แบบย่อใช้จุดสีเพื่อสแกนภาพรวมได้เร็ว แบบขยายแสดงข้อความชื่อเวรในแต่ละวัน
- แตะวันที่ใดก็ได้เพื่อเปิดฟอร์มเพิ่มเวร โดยระบบเลือกวันที่นั้นให้ทันที
- ช่องวันที่แสดงและรับค่าในรูปแบบ `dd/mm/yyyy` โดยใช้ปี พ.ศ. เช่น `18/10/2569`
- วันหนึ่งแสดงได้หลายเวร
- สีของประเภทเวรต้องมี label/text กำกับ ไม่พึ่งสีเพียงอย่างเดียว
- เมื่อเวลาซ้อน แสดง inline alert และให้ผู้ใช้เลือกบันทึกต่อหรือกลับไปแก้
- เวรข้ามรอบนับตามวันที่เริ่มเวร

### Finance

- รายได้คงที่: ฐานเงินเดือนและค่าใบประกอบ
- ค่าเวรตามประเภท
- OT อัตโนมัติและ OT เคสด่วนแยกกัน
- ภาษี ประกันสังคม และรายการหักอื่นที่ผู้ใช้กรอก
- completeness checklist
- ปุ่มยืนยันข้อมูลครบและสร้าง PDF

### Payslip summary

- เป็นเอกสารสรุปส่วนบุคคล ไม่ใช่เอกสารจากนายจ้าง
- แสดงรอบ ชั่วโมง อัตรา จำนวนเงิน และวันที่สร้าง
- พิมพ์ A4 และอ่านบนมือถือได้

### Settings

- รอบเงินเดือนและชั่วโมงปกติ
- รายได้หลัก
- ประเภทเวรและค่าเพิ่ม
- แจ้งเตือนหลายรายการ เปิด/ปิดได้
- ความเป็นส่วนตัว การส่งออก และการลบข้อมูล

## 5. Calculation presentation

```text
OT อัตโนมัติ = ชั่วโมงจากตารางเวรที่เกินชั่วโมงปกติต่อรอบ
OT เคสด่วน = ชั่วโมงเต็มที่ผู้ใช้กรอกเพิ่มและได้รับเงินทันที
OT รวม = OT อัตโนมัติ + OT เคสด่วน

รายได้รวม = ฐานเงินเดือน + ค่าใบประกอบ + ค่าเวร + รายได้ OT + รายได้เพิ่มเติม
เงินสุทธิประมาณการ = รายได้รวม - รายการหักที่ผู้ใช้กรอก
```

เมื่อข้อมูลยังไม่ครบ:

```text
ช่วงประมาณการ = ยอดที่คำนวณได้ - 500 ถึง ยอดที่คำนวณได้ + 500 บาท
```

ตัวอย่าง ยอดคำนวณ 29,500 บาท แสดงเป็น 29,000–30,000 บาท เมื่อข้อมูลครบและได้รับการยืนยันจึงแสดง 29,500 บาท

## 6. Design system

### Visual direction

- Pastel pink, calm, minimal และเป็นมิตร โดยไม่ดูเป็นแอปเด็ก
- ใช้ชมพูพาสเทลหลายระดับร่วมกับ lavender และ peach อ่อนเพื่อแยกหมวดข้อมูล
- พื้นหลังชมพูเกือบขาว ใช้พื้นผิวสีขาวและชมพูอ่อนแยก card
- สี dusty rose ที่เข้มพอใช้เฉพาะ action, icon และสถานะที่เลือก
- ใช้ gradient ที่อยู่ในตระกูลสีใกล้กันเฉพาะปุ่ม, active state และ summary card ไม่ใช้ gradient เต็มทุกพื้นผิว
- ใช้ dot texture จาง ๆ และ pastel blob เพื่อเพิ่มมิติ โดยต้องไม่รบกวนการอ่าน
- ไม่มี glass effect ใช้รูปทรงวงกลมสีพื้นขนาดเล็กเป็น decorative accent เท่านั้น
- Motion ใช้ 180–280ms สำหรับเปลี่ยนหน้า เปิด bottom sheet และ feedback หลังบันทึก ไม่มี animation ที่เคลื่อนไหวต่อเนื่อง

- บ่าย `#9B285B`
- ดึก `#3559A8`

### Typography

- Font stack: `Noto Sans Thai`, `Leelawadee UI`, `Tahoma`, sans-serif
- Display 28/36, Heading 20/28, Body 16/24, Supporting 14/20, Label 12/16
- จำนวนเงินใช้ tabular numerals และไม่ลดต่ำกว่า 20px ใน summary

### Components

- Primary button สูง 48px สีชมพูเข้ม ตัวอักษรสีขาว
- Secondary button สูง 44px พื้นขาว เส้นขอบชมพูอ่อน
- Input สูงอย่างน้อย 48px มี label อยู่ด้านบน ไม่ใช้ placeholder แทน label
- Card radius 18px, input radius 12px, chip radius 999px
- Icon เป็น SVG stroke style เดียวกัน ขนาด 20–24px พร้อม text label
- Tap target ไม่น้อยกว่า 44x44px

## 7. Validation and states

- เวลาซ้อน: warning ไม่ block การบันทึก
- ช่องตัวเลข: ยอมรับเฉพาะค่าตั้งแต่ศูนย์ พร้อม suffix บาท/ชั่วโมง
- OT เคสด่วน: รับจำนวนเต็มชั่วโมง
- Empty state ต้องมี action ชัดเจน เช่น “ยังไม่มีเวร เพิ่มเวรแรก”
- Loading ใช้ skeleton; error มีข้อความสาเหตุและปุ่มลองใหม่
- Offline หรือบันทึกไม่สำเร็จต้องไม่แสดง success

## 8. Accessibility

- contrast ของข้อความและปุ่มต้องผ่าน WCAG AA
- focus ring มองเห็นได้ชัด
- ไม่สื่อสถานะด้วยสีอย่างเดียว
- รองรับ text scaling โดยเนื้อหาไม่ถูกตัด
- PDF ใช้ข้อความจริง ไม่แปลงทั้งหน้าเป็นรูปภาพ

## 9. Approval gate

ก่อนเริ่มเชื่อม LINE/Supabase ต้องอนุมัติ:

- ลำดับหน้าจอและคำเรียกใน UI
- ความหนาแน่นของข้อมูลหน้าหลัก
- โทนสีชมพูและรูปแบบ icon
- รูปแบบเพิ่มเวรและ OT เคสด่วน
- หน้าสรุปและข้อความกำกับยอดประมาณการ
